# IntellectHub Client — режимы разработки (Architect → Code → Debug)

Клиент работает **по порядку через пять режимов**, и все данные всех модов каждого проекта хранятся в его папке `.IntellectHub` и используются при дальнейшей разработке.

## Режимы

| Режим | Команда | Задача | Куда пишет в `.IntellectHub` |
|---|---|---|---|
| **Auto** (Авто) | `/mode auto` | Определяет состояние проекта и спрашивает пользователя, с чего начать | `mode.json` |
| **Orchestrator** (Оркестратор) | `/mode orchestrator` | Разбивает сложную задачу на шаги и координирует остальные режимы | `orchestrator.md` |
| **Architect** (Архитектор) | `/mode architect` | Проектирует архитектуру и строит план **до** написания кода | `architecture.md`, `plan.md` |
| **Code** (Код) | `/mode code` | Пишет и меняет код (инструменты write/edit) | — |
| **Debug** (Отладка) | `/mode debug` | Ищет баги, анализирует логи, исправляет ошибки | `debug-log.md` |

## Порядок прохождения (по умолчанию)

```
новая задача → Авто → Оркестратор → Архитектор → Код
                                                │
                                    ошибка? ◀───┘ (Debug Mode)
                                                │
                                    исправлено ──┘ (снова Код)
```

1. **Auto** — при пустом `.IntellectHub` спрашивает пользователя: «создать архитектуру или посмотреть код?» и **ждёт ответа**. Не принимает решения вместо пользователя.
2. **Orchestrator** — принимает задачу пользователя, разбивает её на шаги и записывает план в `.IntellectHub/plan.md`.
3. **Architect** — описывает архитектуру (`.IntellectHub/architecture.md`) и уточняет план. Код в этом режиме не пишется.
4. Когда архитектура и план готовы — клиент **автоматически** переходит в **Code**. Модель пишет и правит файлы только через инструменты `write`/`edit`.
5. Если инструмент (сборка, тест, запуск) возвращает ошибку — клиент **автоматически** переходит в **Debug**. Ошибка записывается в `.IntellectHub/debug-log.md`, модель анализирует логи и исправляет код.
6. После исправления — обратно в **Code** для проверки.

## Auto Mode — автоматический старт проекта

**Auto Mode полностью автоматический** — клиент сам принимает решение, в какой режим перейти, основываясь на содержимом `.IntellectHub` и файлов проекта на диске. Пользователя не спрашивают.

| Состояние `.IntellectHub` и файлов на диске | Режим | Что происходит |
|---|---|---|
| Пусто (нет ни архитектуры, ни плана, ни кода) | Auto → Architect | Клиент сам начинает с архитектуры (пишет `architecture.md`) |
| Есть архитектура, нет плана | Auto → Architect | Дописывает план (`plan.md`) |
| Есть архитектура + план, нет кода | Auto → Code | Переходит к написанию кода |
| Есть код + ошибки | Auto → Debug | Переходит в отладку, анализирует логи |
| Есть код, ошибок нет | Auto → Code | Продолжает разработку в коде |
| Был Debug, исправлено | Auto → Code | Возвращается к коду для проверки |

Явный выбор через `/mode architect`, `/mode code`, `/mode debug`, `/mode orchestrator` всегда имеет приоритет над автоматическим выбором.

В финале, когда продукт готов, можно сделать последний прогон через **Debug Mode**, чтобы убедиться, что в проекте не осталось проблем.

## Защита от застревания и неконтролируемой работы

Если клиент раньше мог «задуматься и остановиться» или нестись дальше без контроля (например, при создании игры Reigns), теперь работают следующие защиты:

1. **Auto Mode полностью автоматический** — клиент сам определяет состояние проекта и выбирает режим, не спрашивая пользователя. Пустой проект → начинает с архитектуры. Есть архитектура+план → переходит к коду. Есть код+ошибки → отладка.
2. **План сохраняется в `.IntellectHub/plan.md`** — когда модель разбивает задачу на подзадачи, план записывается в файл. При следующем запуске клиент видит готовый план и сразу переходит к коду.
3. **Авто-переход между модами** — после завершения этапа клиент сам переходит к следующему режиму (Architect → Code → Debug → Code).
4. **Остановка при ошибке инструмента или API** — если инструмент или сервер модели возвращают ошибку, ход **останавливается**. Ошибка записывается в `.IntellectHub/mode.json` (`lastError`), клиент переходит в Debug Mode. Модель получает ошибку в следующем ходе и обязана исправить.
5. **Верификация файлов перед завершением подзадачи** — подзадача считается выполненной только если все файлы, которые модель записала через `write/edit`, реально существуют на диске и не пустые. Если файлов нет — клиент просит модель повторить (до 3 попыток), затем пропускает подзадачу как невыполненную.
6. **Реальная проверка наличия кода** — клиент определяет состояние проекта по наличию файлов `.html`, `.css`, `.js` вне `.IntellectHub` и `docs/`, а не по флагам в памяти.
7. **RecordArtifact при каждом write/edit** — при записи любого файла в Code/Debug режиме устанавливается флаг `CodeReady = true`, чтобы клиент знал, что код уже есть.

## Хранение в `.IntellectHub` (на проект)

```
.IntellectHub/
├── mode.json          # текущий режим, история переходов, флаги готовности, pendingQuestion
├── architecture.md    # архитектура приложения (Architect Mode)
├── plan.md            # план реализации (Architect / Orchestrator)
├── debug-log.md       # анализ ошибок и исправления (Debug Mode)
└── orchestrator.md    # заметки координатора (Orchestrator Mode)
```

Файл `mode.json` переносится из сессии в сессию: клиент помнит, на каком этапе была задача, какие флаги (архитектура/план/код готовы) уже выставлены, и не проходит одни и те же шаги дважды.

## Команды клиента

```
/mode               — показать текущий режим и состояние (.IntellectHub)
/mode auto          — автоматический старт: определить состояние проекта и выбрать режим
/mode architect     — перейти в режим Architektura
/mode code          — перейти в режим Кода
/mode debug         — перейти в режим Отладки
/mode orchestrator  — перейти в режим Оркестратора
/mode next          — перейти к следующему режиму по порядку
/mode reset         — сбросить флаги для новой задачи (начинаем с Архитектора)
/mode status        — то же, что /mode без аргументов
```

Также доступно через палитру команд (`⌃K`) как `/mode`.

## Интеграция в цикл агента

- При начале каждого хода клиент определяет активный режим (явный выбор пользователя или автоматическая последовательность) и добавляет в контекст модели напоминание о текущем моде плюс память проекта из `.IntellectHub` (архитектура, план, лог отладки).
- Текущий режим отображается в сайдбаре консоли.
- История переходов модов пишется в `mode.json`, чтобы при следующем запуске разработка продолжалась с того же места.

## Реализация

- `IntellectHub.Client/Mode.cs` — перечисление `Mode` и описания модов (`ModeInfo`).
- `IntellectHub.Client/ModeState.cs` — состояние модов проекта (`ModeState`, `ModeEntry`, `ProjectState`).
- `IntellectHub.Client/ModeStore.cs` — чтение/запись `.IntellectHub/mode.json` и артефактных markdown-файлов, `DetectProjectState()`.
- `IntellectHub.Client/ModeManager.cs` — выбор режима, переходы, флаги готовности, контекст для модели, `AdvanceToNextMode()`.
- `IntellectHub.Client/Program.cs` — команда `/mode`, интеграция в `RunTurnCoreAsync`, `_modes.WithContext(history)`, сохранение плана в `plan.md`, повтор при ошибке инструмента.
- `IntellectHub.Client/Ui.cs` — отображение текущего мода в сайдбаре.
